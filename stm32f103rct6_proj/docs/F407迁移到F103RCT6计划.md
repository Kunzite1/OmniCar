# STM32F407VET6 迁移到 STM32F103RCT6 计划

## 当前状态

截至 2026-09-20，已在 `feature/switch_to_f103rct6` 分支完成 CubeMX 配置、代码生成和第一阶段业务代码迁移，并通过 Git Bash 下的 Debug 全量构建、ST-Link 烧录校验和 USART3 日志自检。尚未完成 LED 实物观察、PWM 波形、CAN 物理链路和电机行为验证。

目标是将原 `stm32_proj/` 中基于 STM32F407VET6 的 OmniCar 应用迁移到 `stm32f103rct6_proj/`，目标芯片为 STM32F103RCT6，LQFP64 封装。

## 已完成的迁移内容

- CubeMX 已配置 HSE 8 MHz、72 MHz 系统时钟、Serial Wire、TIM6 HAL 时基和 FreeRTOS CMSIS-RTOS v2。
- CAN 使用 PA11/PA12，CAN 时钟 36 MHz，`Prescaler=4`、`BS1=15 TQ`、`BS2=2 TQ`、`SJW=1 TQ`，计算速率 500 kbit/s；RX0 中断优先级为 5。
- USART3 使用 PB10/PB11，115200、8N1、无流控。
- TIM3 全重映射到 PC6/PC7/PC8，`Prescaler=0`、`Period=3599`，PWM 频率 20 kHz。
- FreeRTOS 使用 GCC `ARM_CM3` port、`heap_4` 和 16 KB heap；默认任务与 CAN 指令任务均已接入。
- 已迁移 `App/`、`BSP/`、`Middleware/`、`Motion/`，并把 LED、UART、CAN 和电机 BSP 改为 F103 引脚及句柄。
- `32build.sh` 支持 Debug/Release、clean 和并行数；`32flash.sh` 默认先构建，支持 dry-run、跳过构建和可选 SWD 速率。
- 日志支持 DEBUG/INFO/WARN/ERROR/NONE 编译期分级，统一输出 `proj/相对路径:函数名():`；DEBUG 每 10 秒输出一次低频健康摘要。
- DEBUG 全量构建通过，生成 `.elf`、`.bin`、`.hex`；当前 Flash 35,776 B，RAM 22,088 B。
- ST-Link 已以实际 100 kHz 完成烧录、回读校验和复位；USART3 115200 8N1 启动日志确认时钟、PWM/CAN 初始化和 FreeRTOS 任务均已执行。

## 推荐的电机引脚方案

F407 原工程的电机引脚不能直接复制：

- PA5/PA6/PA7 已连接 SPI1 外设；
- STM32F103RCT6 的 LQFP64 封装没有 PE13/PE14；
- STM32F103RCT6 的 LQFP64 封装没有 PD14/PD15；
- 原 F407 的 TIM3 频率参数也不能直接照搬到 72 MHz 的 F103。

在不使用板载 LCD 和 SPI2 的前提下，建议采用下面的映射：

| 功能 | 推荐引脚 | 说明 |
| --- | --- | --- |
| Motor 1 PWM | PC6 | TIM3_CH1，全重映射 |
| Motor 2 PWM | PC7 | TIM3_CH2，全重映射 |
| Motor 3 PWM | PC8 | TIM3_CH3，全重映射 |
| Motor 1 IN1/IN2 | PC4/PC5 | 普通 GPIO |
| Motor 2 IN1/IN2 | PB12/PB13 | 普通 GPIO |
| Motor 3 IN1/IN2 | PB14/PB15 | 普通 GPIO |

该方案保留 PA2/PA3/PA5/PA6/PA7 给板载存储接口，保留 PB6/PB7 供未来 I2C1/IMU 使用，并保持业务层继续使用 TIM3 的三个 PWM 通道。

PC6/PC7/PC8、PB12～PB15 同时连接到板上 LCD 排针，但本项目明确不使用 LCD；如果以后启用 LCD，需要重新规划电机引脚。

## 外设配置目标

### GPIO

- PA8：推挽输出，默认关闭 LED，应用层按高电平点亮处理。
- PC4、PC5、PB12、PB13、PB14、PB15：电机方向推挽输出，默认安全状态。
- PA2、PA3：如果不启用 Flash/TF，仍应配置为输出高电平，避免片选悬空选中外设。
- PA13/PA14：Serial Wire。

### USART3

配置为异步串口：

```text
PB10 -> USART3_TX
PB11 -> USART3_RX
```

不启用硬件流控。PB10/PB11 同时连到 LCD 并口 DB10/DB11，因此不使用 LCD 时可以作为日志串口。

### CAN1

配置为默认引脚：

```text
PA11 -> CAN1_RX
PA12 -> CAN1_TX
```

CAN 位时序必须按 F103 的 36 MHz APB1/CAN 时钟重新计算，不能复制 F407 的参数。目标仍为 500 kbit/s，建议由 CubeMX 重新计算并核对采样点。

PA11/PA12 同时连接 Type-C 的 DM/DP。CAN 工作期间不要插入 Type-C 数据线，也不要把 Type-C 当作本项目供电接口，以避免 USB 主机和 CAN 收发器争用同一对信号线。

原理图没有将 Type-C 通信作为本项目功能，Type-C 并联关系只作为故障排查注意事项保留。

### TIM3 PWM

启用 TIM3 全重映射：

```text
PC6 -> TIM3_CH1
PC7 -> TIM3_CH2
PC8 -> TIM3_CH3
```

F103 的定时器时钟为 72 MHz。若目标 PWM 频率保持约 20 kHz，初始建议：

```text
Prescaler = 0
Period = 3599
```

实际生成后需用时钟树和示波器/逻辑分析仪复核。

### 时钟

目标时钟：

```text
HSE = 8 MHz
PLL = HSE × 9
SYSCLK = 72 MHz
AHB = 72 MHz
APB1 = 36 MHz
APB2 = 72 MHz
```

## FreeRTOS 适配计划

F407 使用 Cortex-M4F，F103 是 Cortex-M3，不能继续使用 `ARM_CM4F` port。

迁移时需要：

1. 使用 FreeRTOS GCC `ARM_CM3` port。
2. 将 F407 的 `stm32f4xx` 头文件、系统文件、中断文件替换为 F1 对应版本。
3. 重新核对 `configPRIO_BITS`、中断优先级和 `configMAX_SYSCALL_INTERRUPT_PRIORITY`。
4. 保持 CAN 接收中断优先级满足 FreeRTOS FromISR API 要求。
5. 优先使用 TIM6 作为 HAL 时间基准，把 SysTick 留给 FreeRTOS。
6. F103RCT6 只有 48 KB SRAM，原工程 `configTOTAL_HEAP_SIZE=32768` 需要重新评估，初始建议降低到 16～20 KB，再根据任务栈水位调整。
7. 重新检查默认任务、日志缓冲区、CAN 队列和环形缓冲区的 RAM 占用。

使用 CH340（USART3 PB10/PB11，115200 8N1）采集日志，并通过 ST-Link/OpenOCD 烧录：

- OpenOCD 识别 Cortex-M3、256 KiB Flash，烧录和 verify 均成功；修正 `32flash.sh` 参数顺序后，日志明确显示 `clock speed 100 kHz`。
- 启动日志确认 SYSCLK/HCLK 为 72 MHz、PCLK1 为 36 MHz、PCLK2 为 72 MHz。

- CAN 控制器正常进入 LISTENING 状态，RX0 中断已启用。当前没有 CAN ACK 对端，发送邮箱最终占满并产生一次限频 WARN，符合台架连接状态。
- `defaultTask` 和 `canTask` 均创建并实际进入；运行约 10 秒时 FreeRTOS 剩余 heap 为 13,728 B，日志丢弃计数为 0。
- 日志路径成功裁剪为 `proj/...:函数名():`，未输出 Windows 绝对路径。

## 构建与烧录命令

在 Windows Git Bash 中，从 `stm32f103rct6_proj/` 执行：

```sh
./32build.sh Debug --clean
./32flash.sh Debug --adapter-speed 100
```

只检查 OpenOCD 命令而不连接、不烧录：

```sh
./32flash.sh Debug --no-build --dry-run --adapter-speed 100
```

板上验证顺序建议为：先观察 PA8 心跳 LED 和 USART3 日志，再测量 PC6/PC7/PC8 的 20 kHz PWM，最后接 CAN 收发器验证 500 kbit/s 心跳帧与 echo。首次验证电机时应断开电机电源或架空车轮，确认方向引脚和占空比安全后再带载。

## 烧录和排查注意事项

- 不要把 CubeMX 的 SYS Debug 设置为 `No Debug`，必须保持 `Serial Wire`。
- 如果再次出现无法连接，使用 NRST 和 Under Reset 连接方式执行全片擦除。
- CAN 工作时不要插 Type-C 数据线。
- 不使用外置 Flash/TF 时，片选线仍应保持高电平。
- 不要把生成的 `build/`、`install/` 或日志文件提交到仓库。
